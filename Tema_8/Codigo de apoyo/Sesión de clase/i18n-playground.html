Antes de empezar: ¿de qué va esto?

Imagina que has hecho una página web o una app (una aplicación: un programa con el que la gente interactúa desde el navegador o el móvil). Si la escribiste en español, una persona de Japón o Alemania la verá toda en español y no entenderá nada.

Podrías hacer una copia de la app por cada idioma… pero sería una pesadilla de mantener. La solución elegante se llama internacionalización, y a eso vamos en esta página.

📖 Cómo usar esta guía: baja tranquilamente de arriba a abajo. Las cajas oscuras son cosas que puedes tocar y probar tú mismo: cambia opciones y mira cómo reacciona. No se rompe nada, experimenta sin miedo.

¿Por qué internacionalizar?

Leer las cosas en tu idioma no es ninguna tontería…

La palabra es larga y rara, así que los programadores la abrevian como i18n. ¿De dónde sale ese "18"? De contar las letras: i + (18 letras en medio) + n = internacionalización. Un truco para no escribirla entera cada vez. 😉

Internacionalizar significa preparar tu app para que pueda mostrarse en varios idiomas y adaptarse a las costumbres de cada país (cómo escriben las fechas, el dinero, etc.) sin tener que reescribir el programa entero cada vez que añades un idioma.

Ojo, no es solo "traducir": también es pensar en el formato del dinero (¿€ o $?), de las fechas (¿08/06 o 06/08?) y en lo que cada cultura espera ver. Hacerlo bien abre tu producto a millones de personas más.

Y a alguien que solo está aprendiendo, ¿por qué le importa esto? Porque marca la diferencia entre una app de juguete y una de verdad:

🧠

Se entiende al instante

Si entro en una web y está en mi idioma, me siento cómodo y no me voy. Si está en otro idioma, me asusto y cierro.

📈

Llega a más gente

Una app en 5 idiomas puede usarla muchísima más gente que una solo en español. Más usuarios, sin reescribir el código.

🎯

Se adapta a cada país

Puedes mostrar precios en la moneda local y mensajes pensados para cada región.

⚖️

A veces es obligatorio

Algunos países exigen por ley que ciertas apps estén disponibles en su idioma oficial.

Dos palabras que verás todo el rato: i18n y l10n

Se parecen, se confunden, pero no son lo mismo.

Igual que "i18n", existe l10n (de l + 10 letras + n = localización). Una analogía para no liarse:

🍽️ Piensa en un restaurante: i18n es construir la cocina para que pueda preparar platos de cualquier país. l10n es cocinar de verdad el plato concreto: la paella española, el sushi japonés… Primero montas la cocina (una vez), luego cocinas cada plato (uno por idioma).
🌐

i18n — Internacionalización

El trabajo técnico de preparar la app: que los textos no estén "pegados" al código, que sepa manejar fechas y monedas de forma flexible. Lo haces una sola vez, al principio.

🗣️

l10n — Localización

Adaptar la app a un país concreto: traducir los textos al francés, poner los precios en yenes, elegir imágenes apropiadas… Lo repites por cada idioma que añadas.

En resumen: i18n hace que tu app pueda hablar otros idiomas; l10n es el acto de enseñarle cada idioma.

El "locale": la pieza más importante

Una etiqueta cortita que le dice a la app "habla así, para esta persona".

Un locale (se pronuncia "locál") es simplemente una etiqueta que indica idioma y, si hace falta, el país. Es como ponerle una pegatina a cada usuario: "este quiere español de España", "este, inglés de EE.UU.".

Estas etiquetas siguen un estándar mundial llamado BCP 47 (no necesitas memorizar el nombre, solo saber que es "la forma oficial de escribirlas"). Tienen esta pinta: es, es-ES, en-US… La parte de antes del guion es el idioma; la de después, la región.

¿Por qué importa la región? Porque el español de España (es-ES) y el de México (es-MX) son el mismo idioma, pero cambian palabras, el formato del dinero y las fechas. La región afina los detalles.

¿Cómo sabe la app qué idioma mostrarte?

A esto se le llama "negociación de locale". Suena complicado, pero es solo seguir una lista de prioridades.

Cuando entras en una web multilingüe, alguien tiene que decidir en qué idioma te la enseña. La app revisa varias pistas, una por una, en orden de importancia, y se queda con la primera que encuentra. A ese proceso se le llama negociación.

Las pistas típicas son: lo que pone en la dirección web (la URL), una cookie (un dato que el navegador guarda de tu visita anterior), tus preferencias de cuenta si has iniciado sesión, y lo que tu navegador dice que prefieres (la cabecera Accept-Language).

👇 Juega con las pistas: activa o quita cada una y observa cuál "gana":

¿Por qué seguir siempre el mismo orden? Para que sea predecible: si recargas la página, debes ver el mismo idioma, no uno distinto cada vez. Si fuera aleatorio, sería confuso y Google tampoco sabría en qué idioma guardar tu página (malo para que te encuentren en buscadores).

Tu ayudante secreto: Intl

Una herramienta que ya viene incluida en JavaScript. No tienes que instalar nada.

Intl (de "internacional") es una herramienta que ya viene de fábrica en JavaScript, el lenguaje que usan las páginas web. No hay que descargarla ni instalarla: ya está ahí, lista para usar.

Su trabajo es formatear cosas según el idioma: le dices "formatéame este número como dinero en español" y te lo devuelve perfecto, con el € detrás y las comas y puntos donde van. Lo mejor: tú escribes el código una vez y funciona para todos los idiomas.

Esto no es un dibujo: lo de abajo se ejecuta de verdad en tu navegador ahora mismo, con la misma herramienta que usarías en un proyecto real. Cambia el idioma y mira cómo el mismo número se escribe distinto en cada uno.

Por fin: cómo se hace en Next.js

Next.js es una herramienta muy popular para crear webs con React. Vamos a ver la idea, sin agobios.

La forma más habitual es meter el idioma dentro de la propia dirección web. Fíjate: miapp.com/es-ES/inicio o miapp.com/en-US/inicio. Esa parte que cambia (es-ES, en-US…) le dice a la página en qué idioma mostrarse.

En Next.js esa "parte que cambia" se consigue con una carpeta especial llamada [locale] (con los corchetes incluidos). Es como decir: "aquí va a ir un idioma, y puede ser cualquiera de los que yo permita".

¿Qué es eso de "SSG"? Significa Static Site Generation (generación de sitio estático). En cristiano: en lugar de construir la página cada vez que alguien la visita, Next.js la fabrica una sola vez de antemano — una versión ya lista por cada idioma. Resultado: páginas rapidísimas y que aparecen bien en Google.

¿Y cómo es el código por dentro?

No hace falta que lo entiendas todo ahora mismo — solo échale un vistazo para perderle el miedo. Cada pestaña muestra un trozo del proyecto con comentarios explicando qué hace:

// La carpeta [locale] = "aquí dentro va el idioma"
app/
└─ [locale]/            // p.ej. es-ES, en-US...
   ├─ layout.tsx       // el "marco" comun de la pagina
   ├─ page.tsx         // la pagina en si
   └─ generateStaticParams.ts  // lista de idiomas a fabricar
dictionaries/          // las traducciones, una por idioma
   ├─ es-ES.json          // textos en espanol
   ├─ en-US.json          // textos en ingles
   └─ fr-FR.json          // textos en frances
middleware.ts          // el "portero": decide el idioma al entrar
// app/[locale]/layout.tsx
export async function generateStaticParams() {
  // SSG: pre-genera una página por cada locale
  return [{ locale: 'es-ES' }, { locale: 'en-US' }, { locale: 'fr-FR' }];
}

export default function RootLayout({ children, params }) {
  return (
    <html lang={params.locale}>
      <body>{children}</body>
    </html>
  );
}
// app/[locale]/page.tsx
import { getDictionary } from '@/lib/dictionaries';

export default async function Home({ params }) {
  const t = await getDictionary(params.locale);
  const precio = new Intl.NumberFormat(params.locale, {
    style: 'currency', currency: 'EUR'
  }).format(29.99);

  return (
    <main>
      <h1>{t.welcome}</h1>
      <button>{t.cta}</button>
      <p>{precio}</p>
    </main>
  );
}
// Un "diccionario" es solo un archivo con los textos
// traducidos. La misma clave ("welcome") en cada idioma.

// dictionaries/es-ES.json
{ "welcome": "Bienvenido", "cta": "Empezar" }

// dictionaries/en-US.json
{ "welcome": "Welcome", "cta": "Get started" }

// En el codigo pides t.welcome y, segun el idioma,
// sale "Bienvenido" o "Welcome". Magia. ✨
// middleware.ts — negocia el locale y redirige
import { match } from '@formatjs/intl-localematcher';

export function middleware(request) {
  const { pathname } = request.nextUrl;
  // 1. ¿ya hay locale en la URL? → no hacer nada
  const hasLocale = locales.some(l => pathname.startsWith(`/${l}`));
  if (hasLocale) return;

  // 2. negocia desde Accept-Language y redirige
  const locale = match(languages, locales, 'es-ES');
  request.nextUrl.pathname = `/${locale}${pathname}`;
  return Response.redirect(request.nextUrl);
}
