Paso 01 · Análisis

Entender qué tiene que hacer Nexus

Antes de tocar SQL o código, conviene aterrizar las funcionalidades del enunciado en entidades, relaciones y endpoints. La actividad cubre dos módulos: la librería universitaria y el co-working. Hay además un módulo transversal de usuarios (aunque el login se trata en otra actividad, los datos del usuario sí se almacenan).

Funcionalidades a sostener desde la API

  • Librería: top 10 más vendidos, categorías de libros/revistas, filtros (año…), ficha individual, libros adquiridos por usuario, compra.
  • Co-working: listado de espacios con disponibilidad, ficha de espacio, reservas.
  • Compartido: usuarios (los crea Auth0 pero se persisten en la BD).
Regla de oro: el login se simulará aparte (Auth0). Todo lo demás sí se implementa con Route Handlers, accediendo a la base de datos PostgreSQL.

Paso 02 · Modelo de datos

Del enunciado al diagrama E/R

Construimos un modelo relacional normalizado (hasta 3FN) que cubre las dos secciones. Decisiones de diseño relevantes:

  • Una sola tabla publications con una columna type ('book' | 'magazine') para libros y revistas. Comparten 90% de los atributos y simplifica los endpoints.
  • Categorías jerárquicas con parent_id autoreferencial, para que existan secciones como Literatura → Narrativa → Novela negra.
  • Autores en N:M con publicaciones via publication_authors.
  • Pedidos con cabecera (orders) y líneas (order_items), guardando el precio al momento de compra.
  • Co-working: un espacio tiene capacidad fija y N reservas; la disponibilidad se calcula con la hora actual NOW().
Por qué evitar dos tablas books y magazines: duplicaría columnas, complicaría el listado conjunto del top-10 y haría incómodos los joins con categorías. La columna discriminadora type es suficiente.

Paso 05 · Scaffolding

Estructura del proyecto Next.js

Usamos el App Router de Next.js 14, donde cada route.ts dentro de app/api/… se convierte en un Route Handler. La organización refleja los recursos REST.

Crear el proyecto

  1. npx create-next-app@latest nexus --typescript --app --eslint
  2. cd nexus && npm install pg zod
  3. npm install -D @types/pg

Paso 06 · Conexión

Cliente único de PostgreSQL

Usamos un pool de conexiones reutilizable. Si lo declaras como global, evitas que el hot reload en desarrollo abra cien conexiones cada vez que guardas un archivo — problema clásico en Next.js.

También definimos un helper query() tipado para no repetir la misma estructura de try/catch en cada handler.

Schemas con Zod

Cada endpoint que recibe un cuerpo (POST de pedido, POST de reserva) usa su z.object para parsear y devolver errores 400 limpios.

lib/db.tsTypeScript
import { Pool, type QueryResultRow } from 'pg';

// Truco anti hot-reload: una sola instancia por proceso
declare global {
  // eslint-disable-next-line no-var
  var __pgPool: Pool | undefined;
}

export const pool =
  global.__pgPool ??
  new Pool({ connectionString: process.env.DATABASE_URL });

if (process.env.NODE_ENV !== 'production') global.__pgPool = pool;

export async function query<T extends QueryResultRow>(
  sql: string,
  params: unknown[] = []
): Promise<T[]> {
  const { rows } = await pool.query<T>(sql, params);
  return rows;
}

Paso 08 · Librería

Route Handlers de publicaciones

Veamos tres handlers de la librería: el listado filtrable, el top 10 y la compra. Todos comparten el mismo patrón: parsear entrada → ejecutar SQL parametrizado (¡nunca concatenar strings!) → devolver NextResponse.json.

1) Listado con filtros dinámicos

Construimos la cláusula WHERE incrementalmente, lo que evita SQL injection y permite combinar cualquier subconjunto de filtros.

2) Top 10 con agregación

El ranking se obtiene con un SUM(quantity) agrupado por publicación, filtrando los pedidos por ventana de tiempo (?days=30).

3) Crear pedido con transacción

La compra requiere atomicidad: insertar la cabecera, insertar las líneas, descontar el stock y todo debe deshacerse si una línea falla. Usamos BEGIN/COMMIT/ROLLBACK con un client dedicado del pool. Si el stock no cubre la cantidad, devolvemos 409.

app/api/publications/route.tsGET listado
import { NextRequest, NextResponse } from 'next/server';
import { query } from '@/lib/db';

export async function GET(req: NextRequest) {
  const sp = req.nextUrl.searchParams;
  const where: string[] = [];
  const params: unknown[] = [];

  const push = (cond: string, value: unknown) => {
    params.push(value);
    where.push(cond.replace('$$', `$${params.length}`));
  };

  if (sp.get('type'))       push('p.type = $$',             sp.get('type'));
  if (sp.get('year'))       push('p.publication_year = $$', Number(sp.get('year')));
  if (sp.get('categoryId')) push('p.category_id = $$',      Number(sp.get('categoryId')));
  if (sp.get('q'))          push('p.title ILIKE $$',         `%${sp.get('q')}%`);

  const sql = `
    SELECT p.id, p.title, p.type, p.price, p.stock, p.publication_year,
           p.cover_url, c.name AS category_name
    FROM publications p
    JOIN categories c ON c.id = p.category_id
    ${where.length ? 'WHERE ' + where.join(' AND ') : ''}
    ORDER BY p.created_at DESC
    LIMIT 100`;

  const rows = await query(sql, params);
  return NextResponse.json({ data: rows });
}
app/api/publications/top/route.tsGET top 10
import { NextRequest, NextResponse } from 'next/server';
import { query } from '@/lib/db';

export async function GET(req: NextRequest) {
  const days = Number(req.nextUrl.searchParams.get('days') ?? 30);

  const rows = await query(`
    SELECT p.id, p.title, p.cover_url, p.price,
           SUM(oi.quantity)::int AS sold
    FROM order_items oi
    JOIN orders o       ON o.id = oi.order_id
    JOIN publications p ON p.id = oi.publication_id
    WHERE o.created_at >= NOW() - ($1 || ' days')::interval
    GROUP BY p.id
    ORDER BY sold DESC
    LIMIT 10`, [days]);

  return NextResponse.json({ data: rows });
}
app/api/orders/route.tsPOST · transacción
import { NextRequest, NextResponse } from 'next/server';
import { pool } from '@/lib/db';
import { OrderSchema } from '@/lib/schemas';

export async function POST(req: NextRequest) {
  const parsed = OrderSchema.safeParse(await req.json());
  if (!parsed.success)
    return NextResponse.json({ error: parsed.error.flatten() }, { status: 400 });

  const { userId, items } = parsed.data;
  const client = await pool.connect();

  try {
    await client.query('BEGIN');

    // 1) Bloqueamos las filas de las publicaciones implicadas (FOR UPDATE)
    const ids = items.map(i => i.publicationId);
    const { rows: pubs } = await client.query(
      `SELECT id, price, stock FROM publications WHERE id = ANY($1) FOR UPDATE`,
      [ids]
    );

    // 2) Comprobamos stock
    let total = 0;
    for (const it of items) {
      const p = pubs.find((x: any) => x.id === it.publicationId);
      if (!p)         throw new Error(`NOT_FOUND:${it.publicationId}`);
      if (p.stock < it.quantity) throw new Error(`OUT_OF_STOCK:${p.id}`);
      total += Number(p.price) * it.quantity;
    }

    // 3) Cabecera
    const { rows: ord } = await client.query(
      `INSERT INTO orders(user_id, total) VALUES ($1,$2) RETURNING id, created_at`,
      [userId, total]
    );
    const orderId = ord[0].id;

    // 4) Líneas + descuento de stock
    for (const it of items) {
      const p = pubs.find((x: any) => x.id === it.publicationId);
      await client.query(
        `INSERT INTO order_items(order_id, publication_id, quantity, unit_price)
         VALUES ($1,$2,$3,$4)`,
        [orderId, it.publicationId, it.quantity, p.price]
      );
      await client.query(
        `UPDATE publications SET stock = stock - $1 WHERE id = $2`,
        [it.quantity, it.publicationId]
      );
    }

    await client.query('COMMIT');
    return NextResponse.json(
      { data: { id: orderId, total, items } },
      { status: 201 }
    );
  } catch (e: any) {
    await client.query('ROLLBACK');
    if (e.message?.startsWith('OUT_OF_STOCK'))
      return NextResponse.json({ error: e.message }, { status: 409 });
    if (e.message?.startsWith('NOT_FOUND'))
      return NextResponse.json({ error: e.message }, { status: 404 });
    return NextResponse.json({ error: 'Error interno' }, { status: 500 });
  } finally {
    client.release();
  }
}
Paso 09 · Co-working

Disponibilidad y reservas

Para el listado, calculamos en SQL el estado actual de cada espacio con un LEFT JOIN LATERAL que trae la reserva activa justo ahora (NOW() entre start_at y end_at) y la próxima en el futuro.

Para crear reservas, debemos comprobar que no haya solapamiento entre intervalos. La lógica clásica: existing.start_at < new.end_at AND existing.end_at > new.start_at. Devolvemos 409 si lo hay.

Reservas parciales: si SUM(seats) + nueva_reserva > capacity, tampoco se admite. Mostrarlo en la vídeo memoria suma puntos en el criterio 3.
app/api/coworking/spaces/route.tsGET
import { NextResponse } from 'next/server';
import { query } from '@/lib/db';

export async function GET() {
  const rows = await query(`
    SELECT s.id, s.name, s.capacity, s.description,
           cur.start_at  AS occupied_since,
           cur.end_at    AS occupied_until,
           cur.user_name AS occupied_by,
           nxt.start_at  AS next_start
    FROM coworking_spaces s
    LEFT JOIN LATERAL (
      SELECT r.start_at, r.end_at, u.name AS user_name
      FROM reservations r JOIN users u ON u.id = r.user_id
      WHERE r.space_id = s.id
        AND NOW() BETWEEN r.start_at AND r.end_at
      LIMIT 1
    ) cur ON true
    LEFT JOIN LATERAL (
      SELECT r.start_at
      FROM reservations r
      WHERE r.space_id = s.id AND r.start_at > NOW()
      ORDER BY r.start_at ASC LIMIT 1
    ) nxt ON true
    ORDER BY s.id`);

  return NextResponse.json({ data: rows });
}
app/api/coworking/reservations/route.tsPOST · sin solapes
import { NextRequest, NextResponse } from 'next/server';
import { pool } from '@/lib/db';
import { ReservationSchema } from '@/lib/schemas';

export async function POST(req: NextRequest) {
  const parsed = ReservationSchema.safeParse(await req.json());
  if (!parsed.success)
    return NextResponse.json({ error: parsed.error.flatten() }, { status: 400 });

  const { userId, spaceId, startAt, endAt, seats } = parsed.data;
  const client = await pool.connect();

  try {
    await client.query('BEGIN');

    // 1) Capacidad del espacio
    const { rows: sp } = await client.query(
      `SELECT capacity FROM coworking_spaces WHERE id = $1 FOR UPDATE`,
      [spaceId]
    );
    if (!sp.length)
      return NextResponse.json({ error: 'Espacio no encontrado' }, { status: 404 });

    // 2) Comprobamos solapamientos y aforo
    const { rows: occ } = await client.query(`
      SELECT COALESCE(SUM(seats), 0)::int AS taken
      FROM reservations
      WHERE space_id = $1
        AND start_at < $3
        AND end_at   > $2`,
      [spaceId, startAt, endAt]);

    if (occ[0].taken + seats > sp[0].capacity) {
      await client.query('ROLLBACK');
      return NextResponse.json(
        { error: 'Aforo superado en el tramo solicitado' },
        { status: 409 });
    }

    // 3) Insertamos
    const { rows: r } = await client.query(`
      INSERT INTO reservations(space_id, user_id, start_at, end_at, seats)
      VALUES ($1,$2,$3,$4,$5)
      RETURNING id, start_at, end_at`,
      [spaceId, userId, startAt, endAt, seats]);

    await client.query('COMMIT');
    return NextResponse.json({ data: r[0] }, { status: 201 });
  } catch {
    await client.query('ROLLBACK');
    return NextResponse.json({ error: 'Error interno' }, { status: 500 });
  } finally {
    client.release();
  }
}

Paso 11 · IA generativa

Documentar el uso de IA

El enunciado es claro: usar IA es obligatorio para (a) generar el modelo relacional DDL y (b) los INSERT de prueba. En la vídeo memoria debes mostrar prompts, resultados y un análisis cuantitativo.

Plantilla de prompt para el modelo relacional

Cuanto más explícito seas con entidades, atributos y relaciones, menos correcciones tendrás que hacer después. Dale a la IA exactamente el bloque de la derecha y exige PostgreSQL.

Métricas que tienes que reportar

  • % de respuestas correctas / parcialmente correctas / incorrectas.
  • Líneas de código generadas con IA (aprox.).
  • Tiempo estimado ahorrado.
Importante: aunque uses IA, siempre revisa el DDL. Errores típicos: poner ON DELETE CASCADE donde no toca, usar FLOAT en vez de NUMERIC para dinero, olvidar CHECKs.

Genera el script DDL completo para una aplicación llamada Nexus que tiene
