Paso 01·Intro

¿Qué es App Router?

El App Router es el sistema de enrutamiento de Next.js basado en la carpeta app/. En lugar de mapear ficheros a rutas per se, mapea carpetas a segmentos y usa archivos especiales (page, layout, loading…) para definir UI, datos y estados.

React Server Components Streaming Layouts anidados Convención sobre configuración

Pages Router legado

  • Carpeta pages/
  • Un fichero = una ruta
  • _app y _document globales
  • Client-side por defecto

App Router actual

  • Carpeta app/
  • Una carpeta = un segmento
  • Layouts anidados por segmento
  • Server Components por defecto

Paso 04·Convenciones

Archivos especiales

Next.js reconoce estos nombres dentro de app/. Pasa el ratón o haz clic en cada tarjeta.

page.tsx

Define la UI única de una ruta. Sin page, el segmento no es navegable.

export default function Page() {
  return <h1>Hola</h1>
}

layout.tsx

UI compartida para un segmento y sus hijos. Persiste entre navegaciones.

export default function Layout({ children }) {
  return <section>{children}</section>
}

loading.tsx

UI de carga con streaming. Se muestra mientras el segmento está suspendido.

export default function Loading() {
  return <p>Cargando…</p>
}

error.tsx

Captura errores del segmento. Debe ser Client Component.

'use client'
export default function Error({ reset }) {
  return <button onClick={reset}>Reintentar</button>
}

not-found.tsx

Se renderiza cuando se llama a notFound() dentro del segmento.

export default function NotFound() {
  return <p>404</p>
}

route.ts

Crea un handler HTTP (API) para el segmento, no una UI.

export async function GET() {
  return Response.json({ ok: true })
}

template.tsx

Como layout pero se remonta en cada navegación.

export default function Template({ children }) {
  return <div>{children}</div>
}

default.tsx

Contenido por defecto para parallel routes sin match.

export default function Default() {
  return null
}

Paso 06·Dinámicas

Rutas dinámicas

Las carpetas entre corchetes capturan segmentos variables y te los pasan como params.

Sintaxis

CarpetaCaptura
[id]Un único segmento
[...slug]Varios segmentos (catch-all)
[[...slug]]Varios segmentos opcionales

Ejemplo: app/blog/[slug]/page.tsx

export default async function Page({
  params,
}: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  return <article>Post: {slug}</article>
}
params = { slug: "nextjs-es-genial" }
render → <article>Post: nextjs-es-genial</article>

Paso 08·Organización

Route Groups

Las carpetas (entre paréntesis) no aparecen en la URL. Sirven para agrupar rutas y compartir layouts sin afectar al path.

Estructura en disco

app/
├── (marketing)/
│   ├── layout.tsx
│   ├── page.tsx
│   └── pricing/page.tsx
└── (shop)/
    ├── layout.tsx
    └── products/page.tsx

URLs resultantes

  • (marketing)/page.tsx → /
  • (marketing)/pricing → /pricing
  • (shop)/products → /products

Los paréntesis se eliminan del path final.

Probador: ¿cuál es la URL real?

app/(auth)/login/page.tsx
app/(marketing)/about/page.tsx
app/(shop)/cart/page.tsx

Paso 10·Componentes

Server vs Client

En App Router, los componentes son Server Components por defecto. Usa 'use client' al principio del fichero para optar por Client.

🌐 Server Component default

  • Se ejecuta en el servidor
  • Puede hacer fetch() de datos directamente
  • Acceso a secretos, BBDD, filesystem
  • 0 KB de JS al cliente
  • No puede usar useState, useEffect, ni eventos del DOM

🖱️ Client Component 'use client'

  • Se ejecuta en el navegador (y se pre-renderiza)
  • Puede usar hooks y eventos
  • No puede acceder a recursos server-only
  • Se envía al bundle del cliente
  • Ideal para interactividad: formularios, menús, animaciones

¿Qué componente usarías?

Leer una variable de entorno con la URL de la BBDD y pintar una lista de productos.

Un <button> que abre un menú desplegable con useState.

Renderizar un artículo de blog con datos traídos desde una API autenticada.

Paso 11·Datos

Data fetching

En Server Components puedes usar async/await directamente. El caché y la revalidación se controlan con opciones del fetch.

const res = await fetch('https://api.example.com/posts')
const posts = await res.json()

Por defecto, el resultado se cachea indefinidamente en build y se sirve estático. Perfecto para datos que no cambian.

Paso 12·Navegación

Redirecciones

Tres formas principales de redirigir, cada una con su momento idóneo.

1 · redirect() en Server

Dentro de Server Components, Route Handlers o Server Actions.

import { redirect } from 'next/navigation'

export default async function Page() {
  const user = await getUser()
  if (!user) redirect('/login')
  return <Dashboard />
}

2 · useRouter() en Client

Redirecciones imperativas tras una interacción.

'use client'
import { useRouter } from 'next/navigation'

export default function Form() {
  const router = useRouter()
  return <button onClick={() => router.push('/ok')}>
    Enviar
  </button>
}

3 · next.config.js

Redirecciones declarativas a nivel de build (301/308 por defecto).

module.exports = {
  async redirects() {
    return [{
      source: '/old-blog/:slug',
      destination: '/blog/:slug',
      permanent: true,
    }]
  },
}

Paso 13·Cheatsheet

Recapitulación

Las diez ideas esenciales que te llevas de este playground.

01

Carpeta app/. Carpetas = segmentos, archivos especiales = comportamiento.

02

page.tsx hace la ruta pública. Sin page, el segmento no responde.

03

layout.tsx envuelve al segmento y persiste entre navegaciones hermanas.

04

[param], [...catch], [[...opt]] capturan segmentos variables.

05

(group) organiza sin afectar la URL. Útil para compartir layouts.

06

loading.tsx y error.tsx crean boundaries automáticos con streaming.

07

Server Components por defecto. 'use client' para interactividad.

08

fetch() con cache y next.revalidate controla estático/ISR/dinámico.

09

redirect() en server, router.push() en client, redirects() en config.

10

route.ts = API del segmento. not-found.tsx = pantalla 404 local.
